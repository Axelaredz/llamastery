## Исправленные недостатки поиска

- Метка `_axis` входила в ключ конфигурации: одинаковые параметры, полученные
  разными путями, могли измеряться заново. Теперь ключ нормализует метаданные,
  числовое написание, bool и неявный V=K.
- Исходный пресет отсутствовал среди screening-кандидатов. Теперь контрольная
  точка измеряется первой; без bench серверный поиск тоже стартует от пресета.
- `max-screen` ограничивал первый список, но не уточнения. Теперь это общий
  лимит, включая baseline, неудачные пробы и refinement. Часть бюджета
  резервируется под уточнение, варианты чередуются между осями.
- Staged-поиск без bench превращался в перебор дефолтов MoE×ubatch. Теперь это
  поиск вокруг лучшей серверной конфигурации с общим `max-candidates`.
- В staged больше нет двойной загрузки каждой модели для отдельного короткого
  предфильтра и полной проверки. Короткий retrieval и затем deep выполняются
  на одном сервере; провал retrieval останавливает глубокую пробу.
- Оси фильтруются отдельно для server/bench и MoE/dense. Число offload-слоёв
  ограничено метаданными. Неизвестная архитектура не включает MoE-ось наугад.
- Убрана связка «изменить decode threads → молча изменить prefill threads».
  Разные типы K/V в исходном пресете сохраняются, логический batch сравнивается
  с его фактическим значением.
- Quantized V при `fa=off` не порождает заведомо неработающих кандидатов.
  Это не доказывает поддержку каждого квантованного типа конкретным backend:
  runtime-проверка остаётся необходимой.
- `fit=off` фиксируется в серверных прогонах, если сборка его поддерживает:
  auto-fit не должен тайком менять проверяемое размещение. При `--apply` этот
  параметр также сохраняется. Auto-fit bench доступен только явным запросом.
- Приоритеты осей больше не учатся на сравнении разных моделей, контекстов и
  зарегистрированных build fingerprint. Fingerprint — путь/размер/mtime
  бинаря, **не** криптографическая аттестация всех библиотек и железа.

## Новые оси и ограничения

| CLI тюнера | Что проверяется | По умолчанию |
|---|---|---|
| `--moe-cache-values auto` или `0,256,512,1024` | `--moe-cache-mib` | `auto`: 0/256/512 MiB, только подтверждённая MoE и доступный флаг; ненулевые варианты — при host-экспертах |
| `--threads-batch-values auto` или `4,8,16` | `--threads-batch` | `auto`: текущее, половина и все логические CPU; число физических ядер не угадывается |
| `--cpu-ffn-values 0,4,8` | `--n-cpu-ffn` | выключено; только dense |
| `--op-offload-values on,off` | `--op-offload` / `--no-op-offload` | выключено, явный A/B |
| `--repack-values on,off` | `--repack` / `--no-repack` | выключено, явный A/B |
| `--backend-sampling-values off,on` | `--backend-sampling` | выключено, экспериментальный server-only A/B |
| `--kv-values q8_0,f16` | пара K/V | существующая политика, пока список не задан |
| `--bench-fit-target 1024` | bench fit margin + `--fit-ctx` | 0: auto-fit не включается |

Новые оси — для **`search=staged`**. `full` оставлен legacy-сеткой; явный запрос
новых осей с `full` отклоняется, а не игнорируется. Ограниченный бюджет не
обещает проверить каждое значение каждой оси — фактически выбранные параметры
записываются в `plan.json`, `screening.json`, `results.json`.

VRAM MoE-кэша добавлена в budget и в идентификатор измерения. Рост кэша
ограничивается наблюдаемым запасом лучшего успешного кандидата, сохраняя
`reserve`. Это предварительный отсев, не гарантия отсутствия OOM.

## Примеры

MoE с частью экспертов в RAM, короткий ограниченный поиск:

```bash
llamastery tune ~/.config/llama/models.ini my-moe --build upstream \
  --extra search=staged search-ctx=16384 \
  moe-values=16,20,24 moe-cache-values=0,256,512 \
  threads-batch-values=4,8,16 max-screen=12 max-candidates=12
```

Список `moe-values` надо выбирать в пределах числа слоёв своей модели.
Нестандартные флаги самой модели остаются в её INI-секции, не в `--extra`.

Отдельная кампания экспериментальных переключателей:

```bash
llamastery tune ~/.config/llama/models.ini my-model --build upstream \
  --extra search=staged search-ctx=8192 skip-screening \
  op-offload-values=on,off repack-values=on,off \
  backend-sampling-values=off,on max-candidates=12
```

Запись победителя — только после полной проверки: отдельный запуск с
`--extra deep apply`, без уменьшенного `search-ctx`. Автоматическая запись
после короткого поиска по-прежнему запрещена.

## Проверка и границы результатов

Пройдены `python tests/run_tests.py` (82 теста) и проверка синтаксиса/CLI help.
Добавлены небольшие fixtures деклараций актуального server/bench help,
проверки capability gating, argv, apply, VRAM, дедупликации и mock-кампания,
проходящая через `main()` без запуска GPU и настоящего сервера.

**Аппаратного A/B здесь не было: ускорение в процентах не заявляется.**
Пробы retrieval используют синтетический повторяющийся текст. Для MoE-кэша,
MTP и backend sampling это не замена тесту на реальном workload. При нескольких
GPU текущий монитор тюнера наблюдает выбранный `--gpu`; распределение кэша
upstream поддерживает, но суммарный reserve по всем картам этот тест не доказывает.
