# preset 注释规范

适用于 `models.ini`（以及任何其他路由 preset）。目标很明确：
文件里的任何数字，要么能被验证，要么被明确标注为估值。

## 三个层级

| 层级 | 标记 | 描述什么 |
|---|---|---|
| 文件 | `; ====` | 硬件、构建、全局规则、模型系列 |
| 系列 | `; ====` | 同一模型的一组相关 preset |
| preset | `; ----` | 一个具体的 preset |

标记不同不是装饰：`=` 用来分隔组，`-` 用来分隔组内的元素。
宽度固定：`-` 为 75 个字符，`=` 为 75 个字符。

## preset 区块

### 符号表

工具写出的字段名是俄语单词，因为 `llamastery presets annotate` 生成的就是它们，
解析器也按它们查找。下文用 emoji 表示，以便本文档保持易读。
**文件里是单词，不是 emoji。**

| 符号 | 文件中的单词 | 含义 |
|---|---|---|
| ✅ | `[замер]` | 实测运行得到的 |
| 🧮 | `[оценка]` | 由 `llamastery budget` 计算，并非实测 |
| 🔬 | `Замер:` | 来源说明：测量的条件 |
| ⚠️ | `Нюанс:` | 陷阱与使用条件 |
| 💬 | `Заметка:` | 逐字保留的旧描述 |
| 🔥 | `ПРОГРЕТО` | 该次试次来自已预热的 KV，不计入 prefill |
| 💥 | `ПАДАЕТ` | 该 preset 曾让服务崩溃 |

```
; ---------------------------------------------------------------------------
; [Tiel-Coder NanoPlus] 65k | 文本 | ngram-mod — 最快的 65k preset
; tg 48.7 t/s  vram 9.9 GiB 🧮  ctx 114688  ub 512
; 🔬 tiel-apply2 2026-09-29, ub=2048, 浏览器约 800 MiB, needle 3/3
; ⚠️ ngram-mod 只在重复文本上有效（代码、模板）；
;    在唯一文本上速度与基础 preset 相同。
; ---------------------------------------------------------------------------
```

### 字段

* **标题** —— 一行：`[模型] 上下文 | 模式 | 差别在哪`。
  诸如「最快」「安全」这类措辞会保留：preset 的选择是按名称进行的，
  而不是靠读注释。
* **指标行** —— 永远只有一行，顺序永远如下：
  `tg <数值> t/s  vram <数值> GiB <标记>  ctx <N>  ub <N>`
  * `<标记>` 为 ✅ 表示实测，为 🧮 表示 `llamastery budget` 的计算结果。
    它只写**一次**，放在行尾，前提是所有带标记的数值来源相同；
    来源不同则各自在原处标注，否则整行会读起来像是两项都实测过。
  * 没有数值就不写数字（工具会填 "не измерено"，即未测量）。编造是禁止的：
    注释里一个错误的数字比没有数字更糟，因为之后会有人引用它。
  * `ctx` 和 `ub` 只在与同系列相邻 preset 不同时才打印 ——
    否则这一行会变成噪声。
  * `moe`（n-cpu-moe）同样按此规则打印：在 MoE 模型上它是最主要的加速杠杆。
* **🔬 来源** —— 得到 ✅ 数值时的条件：调优阶段与日期、
  机器上还跑着什么、探针长度、`needle`。如果没有实测，
  这一行写的是能产生它的命令。
* **⚠️ 注意** —— 陷阱与使用条件，可以占多行。
* **💬 备注** —— 保留**原文**的旧描述：其中存有
  「短的」「在满深度上」「prefill」这类指标里没有的细微差别。
  其中的数字是有意与指标重复的 —— 指标是检索用的索引，
  备注才是事实来源。

### 顺序

标题 → 指标 → 🔬 → ⚠️ → 💬。跳过的区块直接不打印，
不留下空白占位。

指标里的 `tg` 指的是**满上下文深度下的速度**，前提是原始记录中存在 `deep` 行。
`short (4k)` 探针的数值不会进入 tg 字段：4k 探针不足以刻画 preset。
若没有 `deep` 但有 `short`，则取 `short`，并在 🔬 一行中注明。

## `llamastery presets annotate` 会做什么

* 逐字保留所有描述性文字，只改外层结构；
* 把 `=` 风格标题统一为 `-` 风格（旧文件里两种混用）；
* 指标先从调优器实测数据收集，再从旧描述中提取，最后才把
  `llamastery budget` 的计算当作估值 —— 优先级与方法本身一致；
* 不覆盖已写入的指标：重新格式化不应丢失实测数据；
* 幂等：第二次运行报告 0 处改动；
* 不丢弃无法识别的行，而是把它们移到 💬 并在报告中列出。

区块内的表格行不参与描述文本的解析。比较表格中有多列数字，
其中第二列（prefill）曾被误当作 tg，表格的注释也曾被误当作显存实测值。

## 禁止事项

* 在同一区块中混用不同可信度的数字而不加标记。
  相邻 preset 里「约 10.6 GB（实测）」与「约 10.2 GB（安全）」并存，
  是决策出错的来源。
* 把估值写成事实。`llamastery budget` 的计算会高估 compute buffer，
  并把 `n-cpu-moe` 的效果低估约 13%。
* 在区块内两处重复同一指标。数字住在指标行，条件住在 🔬 行。
* 把 `cache-reuse` 与 `mmproj` 放在一起：服务器会自行将其清零。

## 命名约定

`<模型>-<上下文>[k]-<模式>-<加速器>-<视觉>`

```
tiel-coder-nanoplus-65ctx-ngram-mmproj
│                │      │      │      └── mmproj：视觉
│                │      │      └───────── ngram：加速器
│                │      └──────────────── 文本模式（无视觉）
│                └─────────────────────── 65k = 65536 tokens
└───────────────────────────────────────── 模型系列与变体
```

模式后缀：`mtp`、`ngram`、`dflash`。视觉后缀：`mmproj`。
若 preset 中没有外部 draft 头，名称中就不应出现 `mtp` ——
名称必须与内容一致。

## 如何维护

```bash
llamastery presets annotate --dry-run    # 显示将会发生的变化
llamastery presets annotate --apply      # 重写区块（带备份）
```

格式化是幂等的：在已规范化的文件上重复运行不会产生任何改动。
无法识别的行不会被丢弃，而是移入 ⚠️ 并给出警告。
