# llama-swap: export and backend recommendations

`llamastery` is the source of truth (validate + budget + measurements go
directly to `llama-server`); `llama-swap` is only a runtime proxy: one port,
hot-swap, `ttl`. This page covers how to export and which build to run behind it.

## Commands

```bash
llamastery swap export --build faks -o ~/.config/llama-swap/config.yaml --dry-run  # check first
llamastery swap export --build faks -o ~/.config/llama-swap/config.yaml             # write (.bak-<time> backup automatic)
llamastery swap export --build faks --only qwen3.8-35B-A3B-miniplus-v2.1-128ctx     # subset to stdout
llamastery swap status                                # proxy :8080 plus direct server
llamastery swap install                               # download v261 binary to ~/.local/bin (Linux x64 only)
```

## Rules

1. Edit `models.ini`; swap YAML is generated by `export` only. Never hand-edit it.
2. `validate / budget / measure / probe / tune` go direct (`:8099`/`:8098`),
   never via `:8080`. Measuring through the proxy skews timings.
3. One swap config — one build. Never mix `faks` and `ik` in one file:
   flag schemas differ and some flags are silently dropped.
4. Router builds (`faks`, `upstream`) export in single mode via
   `preset_to_argv`. A "swap → router → instance" matryoshka is forbidden.

## Which build to run behind llama-swap (recommendation)

Reference hardware: RTX 3060 12GB + Ryzen 5700X + 32GB RAM.

| Build | When | Swap status |
|---|---|---|
| `faks` | **Default.** The `models.ini` presets were written for it: `n-cpu-moe`, `fa`, `ctx-checkpoints`, `kv-unified`, env `GGML_CUDA_REGISTER_HOST=1` + `GGML_SCHED_PREFETCH_EXPERTS=1`. Clean export, no warnings. | ✅ primary |
| `upstream` | Spare, if `faks` breaks or you need the newest `ggml-org` feature. | ✅ fallback |
| `ik` | Maximum raw MoE speed (IQK/Trellis, FlashMLA), but an old schema (synced Aug 2024): export drops `n-gpu-layers`, `load-mode`, `kv-unified`, `n-predict`. For records load directly with `llamastery load --build ik`; behind swap only as a separate config after checking warnings. | ⚠️ separate |
| `xing4` | Only for `xing4`-architecture models. | ❌ do not mix |

Bottom line: **swap defaults to `faks`** (`swap export --build faks`).
`ik` is for manual records outside swap.

## Run

```bash
~/.local/bin/llama-swap --config ~/.config/llama-swap/config.yaml --listen 0.0.0.0:8080
```

Install method is a binary by choice: host CUDA already works, docker has no
nvidia runtime, and the unified image would lose the Faks patches and require
remapping HF-cache paths.
