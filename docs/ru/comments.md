# Стандарт оформления пресетов

Действует для `models.ini` (и любого другого пресета роутера). Цель — чтобы
любую цифру в файле можно было либо проверить, либо явно назвать оценкой.

## Три уровня

| Уровень | Маркер | Что описывает |
|---|---|---|
| Файл | `; ====` | железо, сборка, глобальные правила, семейства моделей |
| Семейство | `; ====` | группа родственных пресетов одной модели |
| Пресет | `; ----` | конкретный пресет |

Разные маркеры — не украшение: `=` отделяет группу, `-` отделяет элемент
внутри группы. Ширина фиксированная: 75 знаков для `-`, 75 для `=`.

## Блок пресета

Слова меток в файле — русские: их пишет `llamastery presets annotate` и ищет
парсер. В схемах ниже они помечены символами, чтобы читать было легче.

| Символ | Слово в файле | Что описывает |
|---|---|---|
| ✅ | `[замер]` | фактически измеренный прогон |
| 🧮 | `[оценка]` | расчёт `llamastery budget`, не измерение |
| 🔬 | `Замер:` | условия, при которых получено число |
| ⚠️ | `Нюанс:` | ловушки и условия применения |
| 💬 | `Заметка:` | старая проза, сохранённая дословно |
| 🔥 | `ПРОГРЕТО` | проба пришла из прогретого KV, в prefill не идёт |
| 💥 | `ПАДАЕТ` | пресет ронял сервер |

```
; ---------------------------------------------------------------------------
; [Tiel-Coder NanoPlus] 65k | Текст | ngram-mod — САМЫЙ БЫСТРЫЙ пресет 65k
; tg 48.7 t/s  vram 9.9 GiB 🧮  ctx 114688  ub 512
; 🔬 tiel-apply2 2026-09-29, ub=2048, браузер ~800 МиБ, needle 3/3
; ⚠️ ngram-mod работает только на повторяющемся тексте (код, шаблоны);
;    на уникальном тексте скорость равна базовому пресету.
; ---------------------------------------------------------------------------
```

### Поля

* **Заголовок** — одна строка: `[Модель] ctx | режим | чем отличается`.
  Формулировки вида «САМЫЙ БЫСТРЫЙ», «БЕЗОПАСНЫЙ» остаются: выбор пресета
  идёт по названию, а не по чтению комментариев.
* **Строка метрик** — всегда одна, всегда в этом порядке:
  `tg <значение> t/s  vram <значение> GiB <тег>  ctx <N>  ub <N>`
  * `<тег>` — **обязателен** и принимает ровно два значения:
    ✅ — фактически измеренный прогон;
    🧮 — расчёт `llamastery budget`, не измерение.
  * Если значения нет — писать `не измерено`. Выдумывать нельзя: неверная
    цифра в комментарии хуже, чем её отсутствие, потому что на неё потом
    ссылаются.
  * `ctx` и `ub` печатаются, только если отличаются от соседних пресетов
    того же семейства, — иначе строка превращается в шум.
* **🔬 Замер** — условия, при которых получено число с меткой ✅: стадия тюнера
  с датой, что ещё было на машине, длина пробы, `needle`. Если замера не
  было — вместо условий пишется команда, которая его получит.
* **⚠️ Нюанс** — ловушки и условия применения (из старых блоков: ОСОБЕННОСТИ,
  КОГДА ИСПОЛЬЗОВАТЬ). Может занимать несколько строк.
* **💬 Заметка** — старая проза СКОРОСТЬ/ПАМЯТЬ, сохранённая **дословно**:
  в ней остаются тонкости вроде «короткий», «на полной глубине»,
  «prefill», которых нет в метриках. Числа при этом дублируются с метриками
  намеренно — метрика это индекс для поиска, заметка источник истины.

### Порядок

Заголовок → метрики → Замер → Нюанс → Заметка. Пропущенный блок просто не
печатается, пустых строк-заглушек не оставляем.

Значение `tg` в метриках — это **скорость на полной глубине контекста**, если
в исходной записи есть строка `deep`. Значение из пробы `short (4k)` в
tg-поле не попадает: 4k-проба не характеризует пресет. Если `deep` нет, а
`short` есть, берётся `short` и это фиксируется в строке «Замер».

## Что делает `llamastery presets annotate`

* сохраняет всю прозу дословно, меняется только обёртка;
* `=`-стиль заголовков приводит к `-`-стилю (в старом файле они смешаны);
* метрики собирает из замеров тюнера, затем из старой прозы, и лишь потом
  считает оценкой `llamastery budget` — приоритет такой же, как в методе;
* уже записанные значения метрик не перетирает: переформатирование не
  должно терять замеры;
* идемпотентен: повторный прогон даёт 0 изменений;
* нераспознанные строки не выбрасывает, а переносит в «Заметка» и
  перечисляет в отчёте.

## Что запрещено

* Смешивать в одном блоке цифры с разным уровнем доверия без тегов.
  «~10.6 ГБ (замерено)» и «~10.2 ГБ (безопасно)» в соседних пресетах —
  это источник ошибок в решениях.
* Оценку записывать как факт. Расчёт `llamastery budget` завышает compute buffer
  и недооценивает эффект `n-cpu-moe` примерно на 13%.
* Дублировать метрики в двух местах блока. Число живёт в строке метрик,
  условия — в строке «Замер».
* Оставлять `cache-reuse` рядом с `mmproj`: сервер обнуляет его сам.

## Соглашение об именах

`<модель>-<ctx>[k]-<режим>-<ускоритель>-<vision>`

```
tiel-coder-nanoplus-65ctx-ngram-mmproj
│                │      │      │      └── mmproj: зрение
│                │      │      └───────── ngram: ускоритель
│                │      └──────────────── текстовый режим (нет zрения)
│                └─────────────────────── 65k = 65536 токенов
└───────────────────────────────────────── семейство и вариант модели
```

Суффиксы режима: `mtp`, `ngram`, `dflash`. Суффикс зрения: `mmproj`.
Если в пресете нет внешней draft-головы, слово `mtp` в имени не должно
быть — имя обязано совпадать с содержимым.

## Как поддерживать

```bash
llamastery presets annotate --dry-run    # показать, что изменится
llamastery presets annotate --apply      # переписать блоки (с бэкапом)
```

Форматирование идемпотентно: повторный запуск на уже приведённом файле
ничего не меняет. Неопознанные строки не выбрасываются, а переносятся в
«Нюанс», и о них печатается предупреждение.
